# Contributing to PAIMON

Thanks for your interest in PAIMON. This is currently a solo-maintained personal project, so expectations are kept light — but contributions, issues, and forks are welcome.

## Before opening a PR

- Open an issue first for anything non-trivial (new tools, new phases, architectural changes) so we can align before you spend time on it.
- Keep PRs scoped to one change. Small, reviewable diffs are much more likely to get merged quickly.
- Match the existing code style in that repo (each repo has its own lint/format config — run it before pushing).
- Update relevant docs/README alongside code changes, not in a follow-up PR.

## Reporting bugs / requesting features

Use the issue templates provided in each repo. Include repro steps for bugs; include the use case (not just the desired feature) for feature requests.

## Security issues

Do **not** open a public issue for security vulnerabilities — see [SECURITY.md](./SECURITY.md).
